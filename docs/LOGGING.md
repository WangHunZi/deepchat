# 运行日志规范

沿用参考项目的日志正文格式 `[模块::子模块]: 日志`，平台可另加时间戳和级别。
SDK 和第三方库保留上游日志，不复制参考项目中 CoAP 专用字段和日志聚合机制。

| 标签 | 使用场景 |
| --- | --- |
| `[App::Boot]:` | 固件版本、板级配置名称、启动结果 |
| `[Pet::State]:` | 角色交互状态实际发生变化 |
| `[Display::Frame]:` | 屏幕初始化失败或异常帧提交 |
| `[Audio::Capture]:` | 录音开始、完成、达到容量上限或驱动错误 |
| `[Audio::Playback]:` | 播放完成或错误 |
| `[Device::Network]:` | 联网、断线及请求超时 |
| `[Service::Turn]:` | 服务端一轮语音的各阶段耗时与结果 |
| `[Device::Settings]:` | 配置加载或保存结果，不输出配置值 |

- DEBUG 用于诊断；INFO 用于实际状态变化；WARN 用于拒绝操作；ERROR 用于平台或服务失败。
- 错误记录阶段、可读原因及下层原始错误码；不把“请求已提交”写成“播放完成”。
- 跨设备与后端的一轮请求使用同一个关联 ID，目的仅是关联日志，不扩展为持久化事务或重试版本。
- 默认不记录原始录音、识别全文、回复全文、Wi-Fi 密码、访问令牌、API Key 或请求头。
- 只在负责处理错误的边界记录一次，不在逐帧绘制、音频采样或内部判空中刷日志。
- 应用日志采用平台已有日志能力；不新增日志线程、队列、聚合计数或全局日志框架。
- 外部文字作为日志参数，不作为格式字符串；诊断日志不能作为业务完成的唯一信号。
- 核心行为通过返回值和明确的完成事件表达，测试直接验证这些结果。
